# Deploying IntelliTest AI (free tier, no data loss)

**Recommended:** app on **Render** (free web service, Docker) + database on **Neon** (free PostgreSQL).

Why this pair:
- Render's free instances have an **ephemeral disk** — a SQLite file there is wiped on every deploy/restart. Neon is a managed Postgres that keeps your data (0.5 GB free, point-in-time restore), so nothing is lost.
- Uploaded source code is never stored; it lives in a temp folder only while a scan runs. Only findings go to the database, so 0.5 GB lasts a long time.

**Honest speed note:** Render's free service sleeps after 15 minutes without traffic; the first request afterwards takes ~30–60 s. Once awake, pages load instantly, rule/secret/CVE scans finish in seconds, and AI agents add 10–60 s depending on depth. To avoid cold starts, add a free uptime monitor (e.g. UptimeRobot) that requests `https://<your-app>.onrender.com/healthz` every 10 minutes — one always-on service fits in Render's 750 free hours/month. Neon's free compute also suspends when idle and resumes in about a second.

## 1. Database — Neon

1. Sign up at https://neon.tech → **New project** (pick the region closest to your Render region).
2. Copy the **connection string** (`postgres://…?sslmode=require`). Tables are created automatically on first start.

## 2. Code on GitHub

Push this folder to a GitHub repository (the `.gitignore` already excludes `node_modules`, `data`, build output and `.env`).

## 3. App — Render

1. https://render.com → **New → Blueprint** → select the repository. Render reads `render.yaml`.
2. Fill the prompted variables:
   - `DATABASE_URL` — the Neon string.
   - `APP_URL` — `https://<service-name>.onrender.com` (shown after the first deploy; update and redeploy if it differs).
   - Optional: `ANTHROPIC_API_KEY`, `GEMINI_API_KEY` (server-wide default keys; users can also add their own), `GITHUB_TOKEN`.
   - `JWT_SECRET` and `ENC_KEY` are generated by Render once and kept across deploys. **Never change `ENC_KEY`** after users save API keys — they could no longer be decrypted.
3. Deploy. Health check: `/healthz`.

## 4. GitHub sign-in (optional)

1. https://github.com/settings/developers → **New OAuth App**.
2. Homepage URL: your `APP_URL`. Authorization callback URL: `APP_URL` + `/api/auth/github/callback`.
3. Put the Client ID / Client secret into `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET` on Render and redeploy.

Use a separate OAuth app per environment:

| Environment | Callback URL |
|---|---|
| `npm run dev` | `http://localhost:5173/api/auth/github/callback` |
| `npm start` | `http://localhost:8787/api/auth/github/callback` (set `APP_URL=http://localhost:8787`) |
| Windows app | `http://127.0.0.1:47821/api/auth/github/callback` (enter the ID/secret via **File → Edit configuration**; needs port 47821 free) |
| Render | `https://<service>.onrender.com/api/auth/github/callback` |

## Self-hosting with Docker

```bash
docker compose up --build
```

Runs the app plus PostgreSQL with a persistent volume on http://localhost:8787. Set `JWT_SECRET`, `ENC_KEY` and `POSTGRES_PASSWORD` in `.env` first (see `.env.example`); compose refuses to start without the two secrets. Also set `APP_URL=http://localhost:8787` there (or your public URL): a `.env` copied from `.env.example` contains the dev URL `http://localhost:5173`, and GitHub OAuth redirects and secure cookies depend on `APP_URL`.

## Backups

Neon keeps point-in-time history on the free plan (24 h). For long-term copies:

```bash
pg_dump "$DATABASE_URL" > intellitest-backup.sql
```

## Publishing updates

### Web / cloud version
Push to the GitHub branch Render deploys from — Render rebuilds and redeploys automatically (`autoDeploy: true`). Users get the new version on their next page load; data in Neon is untouched.

### Windows desktop app (auto-update)
The installed app checks **GitHub Releases** for a newer version on start-up (and via **Help → Check for updates** or **Settings → About & updates**). It asks before downloading, shows progress on the taskbar, then offers *Restart now*. Scans and settings in `%APPDATA%\IntelliTest AI` are kept.

One-time setup:
1. Create a GitHub repository for the project (it can be private only if users get a token — use a **public** repo or a separate public "releases" repo for simplest updates).
2. Create a GitHub token with **repo** scope (classic) or **Contents: read & write** (fine-grained) for that repo.

Every release:
1. Bump the version in `desktop/package.json` (e.g. `1.0.0` → `1.0.1`). Auto-update only offers *higher* versions.
2. In PowerShell, from the project folder:
   ```powershell
   $env:GH_OWNER = "your-github-username"
   $env:GH_REPO  = "intellitest-ai"
   $env:GH_TOKEN = "ghp_..."
   npm run release:win
   ```
   This builds the installer and uploads `IntelliTest-AI-Setup-<version>.exe`, its `.blockmap` and `latest.yml` to a GitHub Release.
3. On GitHub → Releases, review the release notes (shown to users in the update dialog).

Notes:
- `GH_OWNER`/`GH_REPO` must also be set when you build the **first** installer you hand out (`npm run build:win`) — the update address is baked into each build. Installers built without them can't auto-update; users reinstall once from a build that has them.
- Unsigned builds update fine, but Windows SmartScreen may warn on first install. A code-signing certificate removes the warning.

### Recommended: automatic releases with GitHub Actions
`.github/workflows/release.yml` builds and publishes the Windows installer on GitHub's servers whenever a version tag is pushed — no local build and no personal token (it uses the built-in `GITHUB_TOKEN`).

```powershell
.\release.ps1            # bump version, test, commit, tag, push -> GitHub builds + publishes
```

`.github/workflows/pages.yml` publishes the download page in `site/` to **https://rashvanth2007-byte.github.io/intellitest-ai/**. It always links to the newest installer. One-time setup: repo **Settings → Pages → Source: GitHub Actions**. Once the web version is deployed (Render), put its URL in `WEB_APP_URL` at the bottom of `site/index.html` to show an "Open in browser" button.
